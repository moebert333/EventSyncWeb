# EventSync — UI specification

## Visual direction

Reference site: [https://motocrossactionmag.com](https://motocrossactionmag.com)

Interpret, do not clone:

- Dark, high-contrast race magazine feel (black / charcoal, dirt-bike accent yellow or MX orange, white type)
- **Primary nav in a single row across the top** (desktop); collapse to a hamburger under `768px`
- Bold condensed headlines, large marketing type on Home
- Photography-forward hero; cards with thumb + short dek
- Dense but readable data tables on timing/results (zebra or subtle row hover, sticky header on scroll)

Logo (v1): a motocross racer in a race (static image in `public/`). Owner may replace later. Text wordmark **EventSync** beside the mark.

Safe areas: `env(safe-area-inset-*)` on header and bottom. Tap targets ≥ 44px.

## Global chrome (public)

**Header**

- Logo → `/`
- **Ctrl+click** or **long-press (~1.8s)** on the EventSync brand (logo + wordmark) opens **Simulation mode** (start only from Active Race — see §3b); normal click / short tap still goes Home. Public header only (not admin chrome).
- Nav links: Home · Race Order · Races In Progress · Completed Races · Live Stream
- Actionable controls (buttons, nav links, clickable labels) show a short `title` tooltip on hover
- Right cluster: current **Org name** + **Event name** if a code is resolved; else “Enter event code”
- No Admin link

**Footer** (compact)

- EventSync · read-only companion to the track timing system

**Event / Participant header strip** (shared on Live, Completed Races, Race Order)

Sticky strip under the public header with two lines:

1. **Event:** name and **Rider:** clickable participant (or **Select Rider**). Opens the shared Select participant panel.
2. Page title (left) and **Warning text** (right) when a Selected participant is set for this event.

**Warning text** (Title Box link to `/order`, skips the Race Order progress toast):

- Always title-cased. Remains a link in every case below.
- Distance to “next” is the event `race_num` gap (`nextNum − activeNum`), including races the rider is not entered in.
- When a **Practice** is active, substitute **Practice** for **Race** in all copy below **except** rule 1 (always first competitive Race).
- Yellow background cases use **black** text (not inherited page/link color).

| # | Condition | Warning text | Style |
|---|---|---|---|
| 1 | No Race or Practice is active | `Your First Race is {num}` — first competitive Race for this rider (not Practice). Blank if the rider has no competitive races. | Normal gold link |
| 2 | Next session is more than 2 races away | `Your Next Race is {num}` | Normal gold link |
| 3 | Rider is **not** in the current race; next is 1 or 2 races away | `Your Next Race is {num}` | Yellow background, black text, **not** flashing |
| 4a | Rider is in current race; status **Staging**; has a later session | `Your Next Race is {num}` | Normal gold link |
| 4a | Rider is in current race; status **Staging**; no later session | `You are in this Race` | Yellow background, black text, **flashing** |
| 4b | Rider is in current race; status **Active** or **Paused**; has a later session | `Your Next Race is {num}` | Normal gold link |
| 4b | Rider is in current race; status **Active** or **Paused**; no later session | `You Have No More Races` | Normal gold link |
| 4c | Rider is in current race; status **Finished**; has a later session | `Your Next Race is {num}` | Normal gold link |
| 4c | Rider is in current race; status **Finished**; no later session | `You Have No More Races` | Normal gold link |
| 5 | Rider is not in the current race; no remaining sessions in the active pool | `You Have No More Races` | Normal gold link |

Session pool: when a Practice is active, count Practices only; otherwise competitive races only. When nothing is active, rule 1 uses competitive races only.

**Warning Popup** (full-screen dismissible overlay; generates a browser Notification when the popup message changes **or** the active race changes even if the text is the same):

| # | Condition | Popup message | Box style |
|---|---|---|---|
| 1 | No Race or Practice is active | None | — |
| 2 | Next session more than 2 races away | None | — |
| 3 | Rider not in current race; next is 1 or 2 away | `Your Next Race is Staging` | Yellow, **not** flashing |
| 4a | Rider in current; **Staging** | `Your Race is Staging` | Yellow, **flashing** |
| 4b | Rider in current; **Active** or **Paused** | `You are in this Race` | Yellow, **flashing** |
| 4c | Rider in current; **Finished**; next is 1 or 2 away | `Your Next Race is Staging` (same as rule 3) | Yellow, **not** flashing |
| 4c | Rider in current; **Finished**; otherwise | None | — |
| 5 | Rider not in current; no remaining sessions | None | — |

Popup copy is title-cased. Practice substitution applies the same as Warning text (except there is no popup for rule 1).

**Live Stream** may show a “Coming soon” page until phase 7.

Admin is **`/admin`** only, typed or bookmarked.

## Screens

### 1. Home `/`

Layout (desktop): two columns.

**Left / main**

- Hero logo image and marketing headline on one wrapping row (icon left, headline right), e.g. “Live laps. Staging. Results. Don’t miss your moto.”
- **Event Code** field: 4–12 characters, submit button “Go to event”
- On success: badge with organization + event + date/track if present; clicking the badge routes like Ok/Skip after event selection (Live if Staging/Active/Paused, otherwise Completed Races)
- On failure: inline error “That Event Code was not found”
- After an event is selected or changed: show the shared **Select participant** panel (optional; search name/plate + Select a Rider) with **Ok** and **Skip**. Persist choice in `localStorage` key `eventsync.selectedParticipant` (event id, participant id, name, plate). Clear when the Event Code resolves to a different event. Skip leaves an existing selection unchanged. Typing in search shows matching riders in a list; choosing a rider selects them and continues as **Ok**.
- After Ok or Skip: go to **Races In Progress** if the current race status is Staging, Active, or Paused; otherwise go to **Completed Races** (Finished, Waiting, or no in-progress row).

**Right rail**

- Heading: “MX / SX News”
- Vertical list of article cards: image, title, 1–2 line summary, external link (new tab)
- v1: 4–8 curated static items if no `news_articles` table

**Below fold (optional):** three feature tiles linking to Live / Results / Stream.

### 2. Organization Admin `/admin`

Not in public nav.

**Unauthenticated**

- Email field + “Email me a sign-in link”
- Copy: link expires; check spam; no password
- After send: “Check your inbox”

**Callback `/admin/callback`**

- Complete session
- If email not on `admin_allowlist` or inactive: sign out, message “This email is not authorized to manage events”
- Else route to `/admin`

**Authenticated admin**

Three stacked panels (can be tabs on mobile):

1. **Organization** — name, description; create first org or edit the allowlisted org
2. **Series** — list for that org; add/edit name + description
3. **Events** — list for selected series; fields from schema: `name`, `description`, `date`, `track`, `location`
4. **Event Code** — for selected event: 4–12 chars; **prefill a random default** (e.g. 8 chars A–Z0–9 excluding ambiguous `O/0/I/1`); admin may edit; unique across table
5. **QR** — show a QR image of `https://<origin>/?code=<CODE>` for printing (generate client-side)
6. Sign out

No UI for timing, participants, or allowlist management in MVP.

Validation errors from unique names / codes shown next to the field.

### 3. Races In Progress `/live`

Modern magazine header strip + data.

**If no in-progress row** (`race_in_progress` empty for this event/series):

- Empty state: “No race is staging or on track right now.”
- Link to Results

**If one race** (MVP: only one in progress):

- Shared **Event / Participant header strip** (see Global chrome): Warning text + Warning Popup rules; clicking Rider opens Select participant (Ok, Skip, or choosing a rider closes it; Skip does not clear an existing selection). Choosing or confirming a participant re-applies page rules (class/row on Live; first class results on Completed).
- Below that, top to bottom: the race-number line; session name and race date/start; either the progress chart or the status video (when open); then the class chips
- Race-number line: race number, status pill (`Waiting` / `Staging` / `Active` / `Paused` / `Finished`), a chart-icon button immediately to the right of the status pill, and a video-icon button beside the chart icon whenever a status video exists for the current race status
- Status pill colors (contrasting text): Waiting light grey, Staging lighter orange, Active green, Paused yellow, Finished light blue. Clicking the pill shows the message `Race status: {status}`
- Class chips from `race_class_names` for that `race_id`. If that view is empty, use class names present on the timing rows.
- Chips are buttons (rectangle labels). Exactly one class is selected, or **All Classes** (a button to the right of the class chips). On load, select the first class. The selected chip uses a solid accent background. A class chip shows only that class. All Classes shows every class in one table.
- When switching to this page, if a Selected participant is set and that participant appears in any class of the current race, switch to that class, select that row, and open the progress chart for them. The user may change class/row afterward; this apply runs once per shown race.
- When a **new** race is detected while this page is already open: close the chart if it was open and open the status video (when that status has media). Still select the Selected participant’s class/row when they are in the race, but do not reopen the chart over the video.
- Table from `active_race_timing` for the selected class. No Class column (the selected chip names the class). A single class starts sorted by place. All Classes adds a Class column and starts sorted by class, then place. Clicking any column name sorts the table (click again reverses it); ties still break by class, then place:
  - Class (All Classes only)
  - Place (`place_num` already label-aware)
  - Plate
  - Rider (`first_name` `last_name`)
  - Lap
  - Lap Time (current lap time)
  - Best lap (`#n - time`)
  - Elapsed
  - Gap to leader
  - Gap to next
  - Status
- On the class-name line, just above the table and to the right of the class name, show **Elapsed Time:** plus `race_in_progress.elapsed_race_time` (or `status.elapsed_race_time`) formatted to whole seconds (`HH:MM:SS`). While status is `Active`, advance that display every second locally between polls, resyncing when a new server value arrives; freeze it for Staging / Paused / Finished. To the right of that line, show a clickable green highlight-mode control (black text on the same light green used for the highlighted row). Default label **Best Lap Time**. Clicking opens a menu: **1st Place**, **Best Lap Time**, **Participant**. The chosen option replaces the label and drives which visible row gets the light green highlight:
  - **1st Place** — the row with place `1` (lowest participant id if more than one)
  - **Best Lap Time** — after at least one visible row has lap number ≥ 1, the participant on the greatest lap number whose current lap time is the lowest; ties break by better place, then participant id
  - **Participant** — the Selected participant’s row when that rider is in the visible table; otherwise no green highlight
  - If the highlighted row is also selected, keep the light green fill and a visible selection edge
- Click a row to select that participant and open the progress chart (the chart button is selected and the video closes). The selected row is shaded light grey.
- As each timing poll is applied, save **in the browser only** (`localStorage` key `eventsync.lapProgress`, not Supabase) one sample per participant per lap: place, lap time, best lap time, gap to leader, and gap to next. A later poll for the same lap replaces that sample. Scope by `race_id`, `class_id`, and `participant_id`. History survives refresh for that same race. Laps are recorded only for polls the page actually sees.
- Clear that saved chart data when a different race is shown (`race_id` changes). The new race starts with an empty chart.
- Clear it when a poll shows the race restarting: every reported `place_num` is `0`. Do not record that poll. Later polls with real places start a new chart.
- The chart button toggles a line chart directly above the class chips. Clicking a table row opens that chart for the clicked participant. The chart is for the selected row, or the first row of the selected class if none is selected.
  - X axis: lap number
  - Left and right Y axes are chosen from Place, Lap Time, Best Lap, Gap to Leader, and Gap to Next. Defaults are Place on the left and Lap Time on the right
  - Clicking the chart legend reveals a Left axis dropdown, a Right axis dropdown, and a Save button. Save writes the choice to this browser (`localStorage` key `eventsync.chartAxes`), hides the dropdowns and button, and shows the updated legend. A click outside the legend discards unsaved changes and restores the previous legend. The chart keeps using the saved axes until Save. Defaults are Place and Lap Time when nothing is stored yet
  - Place is drawn with 1st toward the top. Lap Time, Best Lap, Gap to Leader, and Gap to Next are drawn with the smaller value toward the bottom
  - Two lines, from the local progress samples
  - Until that participant has 2 stored laps, the chart area reads “Chart is Waiting for 2 Laps Data...”
- The video button toggles a looping muted status video in that same slot (files in `public/videos/`):
  - `Staging` → `start_race.mp4`
  - `Active` → `active_race.mp4`
  - `Paused` → `pause_race.jpg` (still image in the same slot, only while the video button is selected)
  - `Finished` → `finish_race.mp4`
  - Other statuses: no media and no video-icon button
- Chart and video share one slot. Selecting either icon opens that panel and unselects the other. Unselecting either icon closes only that panel and leaves the other icon’s state unchanged. Clicking a table row opens the chart and unselects the video. Opening or selecting the page leaves the video closed. When a new race starts while the page is open, the video starts open if that race status has a video; otherwise both start closed. The chart always starts closed.
- When status is `Finished`, keep showing the race header and the current `active_race_timing` table (do not clear the table). Poll the race header so a later Staging/Active race can replace it; stop polling timing rows until the race is live again.
- When `race_in_progress` is empty for the event, keep polling the race header so a newly active race appears automatically (no manual refresh).
- Auto-refresh timing while status in Staging/Active/Paused
- Times are `time` values; display as `m:ss.xx` if the stored value supports it, else `HH:MM:SS`

Do not invent a second concurrent race UI. Do not write lap history back to `race_timing`.

### 3b. Simulation mode (client-only)

Hidden demo/development mode so `/live` can run without a real track feed. **Never** insert/update `active_timing`, `status`, `races`, or related timing tables.

**Entry**

- Simulation may only be **started** while the user is on **Active Race** (`/live`).
- Ctrl+click (desktop) or long-press ~1.8s (touch) the public header EventSync brand (logo + “EventSync”).
- Opens a dialog matching other overlays (portal, gold border, Ok / Cancel).
- Off `/live` (and not already simulating): dialog explains to go to Active Race; no start.
- Requires a resolved Event Code. If none, show a short message and disable Ok.
- While a simulation is already running, the same Ctrl+click reopens the dialog with **Stop simulation**.

**Dialog fields**

- **Race** — list races for the current event from the same race-order source as `/order`, **excluding practices** (`is_practice`). Prefer defaulting to an active race, else first incomplete, else first race.
- **Approx. lap time (seconds)** — number input, default **15**. Valid range **2–120** (inclusive). Clamp on blur; reject Ok outside range with an inline error.
- **Ok** — start simulation, close dialog, navigate to `/live`.
- **Cancel** — close without starting (or without stopping, if already running and Stop was not chosen).

**Runtime behavior**

- Seed entrants read-only from `active_race_participants` for the chosen `race_id` + event (fallback: `race_class` + `event_entry` + `participants`). Timing values are synthetic only.
- On start, populate one **lap 0** timing row per entrant with zero/empty timing (`place` 0, times `00:00:00`) so the Active Race table shows the field before the first crossing.
- Drive in-memory data shaped like `race_in_progress` + `active_race_timing`. Override the live page hooks for that event while active; do not poll those Supabase views in parallel for the simulated event.
- Race status starts **Active**. Vary per-rider pace (stable skill factor + per-lap jitter). Recompute place and gaps **only when a lap is recorded**; freeze prior lap rows (append-only history so the progress chart still works).
- Header elapsed race time advances while Active; freezes while Paused.
- Race Order, Results, and Staging alerts stay on real DB data (simulation does not flip `races.active` or `status` in Supabase).

**Banner (under public header while simulating)**

- Label: `Simulation · {race title}`; when paused, include `Paused`.
- While simulating on `/live`, show **only** this simulation banner — hide the Active Race `EventParticipantHeader` strip until the simulation stops.
- **Pause** — freeze elapsed and lap generation; set simulated status to `Paused`; button becomes **Continue**.
- **Continue** — resume from the same race elapsed (do not advance for wall-clock time spent paused); status back to `Active`.
- **Stop** — end simulation, clear in-memory data, resume normal Supabase polls for `/live`.

**Leaving Active Race while simulating**

- Navigating away from `/live` (nav link, home brand without Ctrl, browser back, etc.) is blocked with a confirm dialog: **Simulation will be Cancelled.** with **Ok** / **Cancel**.
- **Cancel** — stay on `/live`; simulation keeps running.
- **Ok** — stop simulation, then complete the navigation.

**Exit**

- Stop from the banner, or Ctrl+click brand → Stop simulation.
- Ok on the leave-confirm dialog (above).
- Switching Event Code / event context while simulating also stops simulation.

### 4. Completed Races `/results`

Page title: **Completed Race Results** in green text (compact size).

At the top: same shared **Event / Participant header strip** (Warning text + Warning Popup) as Races In Progress; clicking Rider opens the Select participant panel.

**Select Results panel**

- Header label: **Select Results Filter:** with an up/down control to expand or collapse the filter form (saves space while viewing results). When collapsed, the bar is only slightly taller than the label text. Event name is already shown in the page header above.
- **Show results** collapses the panel and loads the grid.
- When navigating here with a Selected participant for the Event Code’s event: if that rider is entered in at least one class for the event, select **Filter by: Class**, pick the first class name (sorted), load that class’s results, and leave the panel **collapsed**. If there is no Selected participant or no class entry match, leave the panel **expanded**.

**Filters (in order, when expanded)**

1. Organization label and name on one line **read-only** (from Event Code)
2. Series: All series | pick series in this org
3. Event: dropdown of events in that org (filtered by series). Default = event from Event Code
4. Then either:
   - Class name (from classes for selected event), or
   - Participant (search/select name or plate in that event)
5. Button **Show results**

Changing the Participant dropdown also updates the app-wide Selected participant (or clears it when the dropdown is cleared).

**Results list**

- One row per event + class + participant from `event_class_results`
- Columns: class, place, plate, name, make, overall points, race1–3 places, semi1/2, LCQ, finals (hide empty columns if every value null for the result set)
- When a Selected participant is set for the results event and that rider appears in the grid, shade their row light grey
- Empty: “No results posted for this selection yet.”
- Error: retry + message

**Client Place / Points enrichment (display only)**

Per class, after fetch from `event_class_results` (no writes back to Supabase):

1. If any `overall_points` in the class is non-zero, leave the class unchanged (already scored).
2. If every `overall_points` is **0 or null** and any `overall_place` parses to a number **greater than 0**, keep those Place values and fill Points only (step 7 gates) from `event_points` by Place; do not recalculate Place.
3. Otherwise, if every `overall_points` is **0 or null** (and no numeric Place), calculate Place and Points for display as below.
4. **Max moto (per class):** from Race Order (`races.session_name` for races that include the class), parse `MOTO` + integer (e.g. `DIV::1::MOTO 2` → 2). Max moto = largest such number. Sessions without `MOTO` (e.g. Final) do not set max moto.
5. Scoring columns: when max moto is known, use Moto 1…max (capped at 3) columns that have at least one value class-wide. Else if Final has values, use Final alone. Never Semi or LCQ.
6. Place: sum each rider’s scoring-column values (non-numeric → **80**). Rank ascending by sum (lowest total = Place 1). Ties: better (lower) finish in the last scoring column wins. Riders with no numeric scoring values rank last; order among them unconstrained.
7. Points: map Place → `event_points.points` for that event’s `position`. Riders with no numeric scoring values (or no numeric Place on the Points-only path) → **0**. Missing `event_points` row → **0**. `DNS/DNF`, null, empty, and `0` do not count as a scored moto. Env `VITE_REQUIRE_ALL_MOTOS` (default **false**): when **false**, assign Points once any one moto `1…max` is numerically scored; when **true**, require every moto `1…max` before Points (otherwise Place with Points **0**). Final-only classes (no max moto) still get Points when calculating. When no Points are scored yet for a class, still show the Points column with **0** per row.
8. When max moto is known, always show Moto 1…max columns for that class; unscored moto cells display as **—**.

User may change event within the same organization without a new code.

### 5. Race Order `/order`

Assumes races run in `race_num` order. Completion uses `races.completed`; the current race uses `races.active`.

- Same shared **Event / Participant header strip** (Warning text + Warning Popup) as Live / Completed
- Title: **Race Order**
- List all races for the Event Code event ordered by `race_num`
- Each race row: race number, name, session; expand/collapse to show class names from `race_class` / classes
- Status by color and label: **Completed**, **Active**, and (when Selected participant is entered in that race via `event_entry` → `race_class`) **Participant**
- Empty and error states with retry

Announcements / prepare-staging block remain FUTURE.

### 6. FUTURE — Live Stream `/stream`

v1 header may include the link → “Coming soon”.

Recommended approach when built (not MVP):

- Organization supplies **HLS** (`.m3u8`) URLs per camera, stored per event
