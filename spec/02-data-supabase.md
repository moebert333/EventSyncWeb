# EventSync — Data and Supabase

## Source of truth

Race timing, entries, and results are written by the **local race application**, not this website.

This app:

- **Public:** `SELECT` on views/tables allowed by RLS, filtered by organization from Event Code.
- **Admin:** `INSERT/UPDATE` (and limited `DELETE`) on `organizations`, `series`, `events`, `event_codes` only.

## Existing public schema (from CreateAllTables.sql)

Hierarchy:

```text
organizations
  └── series
        └── events
              ├── event_codes (1:1, Event Code string)
              ├── races
              │     ├── status (1:1 live clock / race_status)
              │     ├── race_class → classes
              │     ├── active_timing
              │     └── race_timing
              ├── classes
              ├── event_entry
              └── event_results
participants (org-scoped)
```

### Tables (as provided)

| Table | Role |
|---|---|
| `organizations` | Org name unique |
| `series` | Belongs to org; unique `(organization_id, name)` |
| `events` | Belongs to series; unique `(series_id, name)`; optional `date`, `track`, `location`, `active_race_id` |
| `event_codes` | PK `event_id` → `events`; `code` text |
| `races` | `race_num`, `session_name`, `completed`, `active` |
| `classes` | Per event; unique `(event_id, class_name)` |
| `race_class` | Which classes run in a race |
| `status` | Live race clock; enum `race_status` |
| `participants` | Org-level people; `participant_id` is **not** identity in current SQL |
| `event_entry` | Registration; plate on the entry |
| `event_results` | Overall + moto/semi/LCQ/final columns |
| `active_timing` | Latest lap row per (race, class, participant) |
| `race_timing` | Full lap history |

Enum `public.race_status`: `Waiting`, `Staging`, `Active`, `Paused`, `Finished`, `Cancelled`.

Function `place_label(pos int)`: `NULL` → null; `> 80` → `DNS/DNF`; else position text.

### Views the UI must use

| View | Page |
|---|---|
| `race_in_progress` | Races In Progress header (0 or 1 row per series/event filter) |
| `active_race_timing` | Timing rows (place, laps, gaps, names, plates) |
| `event_class_results` | Completed Races grid |
| `race_class_names` | Classes under a race; Race order page later |

`race_in_progress` already joins `races` + `events` + `status` where `races.active` is true and status ∈ (`Staging`, `Active`, `Paused`, `Finished`). Finished stays in the view so the live page can keep showing that race and its `active_race_timing` rows until the race is no longer active.

## Schema additions required for this website

Apply in Supabase SQL editor (keep in `supabase/migrations/` in the repo).

### 1. Event Code uniqueness and shape

Current `event_codes.code` has no unique constraint.

```sql
alter table public.event_codes
  add constraint event_codes_code_key unique (code);

alter table public.event_codes
  add constraint event_codes_code_len
  check (char_length(code) between 6 and 12);
```

Codes are matched **case-insensitively** in the app (`lower(code)`). Prefer storing uppercase.

Optional generated column later; v1 can normalize in the admin form.

Note: `event_codes.event_id` is declared `generated by default as identity` **and** FK to `events.event_id`. Treat it as the event’s id (insert with explicit `event_id`, do not rely on a second identity sequence). Admin insert: after creating `events` row, insert `event_codes (event_id, code)`.

### 2. Admin allowlist (magic link gate)

```sql
create table public.admin_allowlist (
  allowlist_id bigint generated by default as identity primary key,
  created_at   timestamptz not null default now(),
  email        text not null,
  organization_id bigint null references public.organizations(organization_id) on delete set null,
  is_active    boolean not null default true,
  constraint admin_allowlist_email_key unique (email)
);

create index admin_allowlist_email_lower_idx
  on public.admin_allowlist (lower(email));
```

- `organization_id` null = may administer any org (platform operator).
- Non-null = may administer only that organization.
- Seed first admin emails in SQL; no public UI to add allowlist rows in MVP.

### 3. Optional news table (Home right rail)

Home asks for MX/SX article cards. v1 may use a **static curated list** in code (title, summary, image URL, href) so the site works before a CMS exists.

If using Supabase later:

```sql
create table public.news_articles (
  article_id   bigint generated by default as identity primary key,
  created_at   timestamptz not null default now(),
  published_at timestamptz not null default now(),
  title        text not null,
  summary      text not null,
  image_url    text not null,
  article_url  text not null,
  is_published boolean not null default true
);
```

Do not block Home on this table.

## Row Level Security

Enable RLS on **all** public tables and views that the client touches. Views should run as invoker (`security_invoker = true` on PG15+) so underlying table RLS applies.

### Spectator (anon key, no user)

Allow `SELECT` on:

- `organizations`, `series`, `events`, `event_codes`
- `races`, `classes`, `race_class`, `status`
- `participants`, `event_entry`, `event_results`
- `active_timing`, `race_timing`
- views listed above

Deny `INSERT/UPDATE/DELETE` for `anon` on every table.

Application still **must** filter by `organization_id` from the resolved Event Code. RLS for “this org only” is hard for fully anonymous users without a JWT claim. v1 approach:

1. Anon can `SELECT` event_codes + joined public race data (all orgs readable at API level) **or**
2. Prefer tightening later with a Supabase Edge Function that mints a short-lived JWT containing `organization_id` after code check.

**Spec decision for MVP:** anon `SELECT` allowed on the listed objects; **UI and query layer always filter by resolved org/event**. Document this as known limitation. Do not expose admin tables.

### Authenticated admin

```text
admin_allowlist: SELECT own email row only (auth.jwt() ->> 'email')
organizations / series / events / event_codes:
  INSERT/UPDATE/DELETE only if lower(auth email) is an active allowlist row
  and (allowlist.organization_id is null or matches the row’s org)
```

`SELECT` on allowlist of other emails: denied.

No client writes to timing/results/participants.

## Query recipes

### Resolve Event Code

```sql
select
  ec.code,
  e.event_id, e.name as event_name, e.date, e.track, e.location, e.series_id,
  s.name as series_name, s.organization_id,
  o.name as organization_name
from public.event_codes ec
join public.events e on e.event_id = ec.event_id
join public.series s on s.series_id = e.series_id
join public.organizations o on o.organization_id = s.organization_id
where lower(ec.code) = lower($code);
```

### In-progress race for current event

```sql
select * from public.race_in_progress
where event_id = $event_id;
```

Fallback if empty: `where series_id = $series_id`.

### Timing rows

```sql
select * from public.active_race_timing
where race_id = $race_id
order by class_name, place_num;
```

The Races In Progress page shows one class at a time. It does not read `race_timing` for the progress chart.

### Client lap progress

The website does not insert timing rows. As `active_race_timing` polls arrive, the page stores the latest place, lap time, best lap time, gap to leader, and gap to next for each participant and lap in `localStorage` key `eventsync.lapProgress`, for the shown `race_id` only. That cache only feeds the progress chart and must not be written back to Supabase. Clear it when the shown race changes, and when a poll reports place `0` for every placed row (the race is restarting). Do not record the restart poll. Refresh on the same race keeps the chart.

### Completed results

```sql
select * from public.event_class_results
where event_id = $event_id
-- and class_name = $class
-- and participant_id = $participant_id
order by class_name, overall_place;
```

`overall_place` is text (`DNS/DNF` possible); sort using underlying `overall_position` if needed by selecting from `event_results` instead of the view.
